# ERPNext 库存与发货工作台前端（新增）

本目录是新增 Vue 3 + TypeScript + Element Plus 界面，支持单企业内部多账号协作。诊断任务、证据与权限由 HolmesGPT 新增的同源 FastAPI 服务提供，页面不生成示例诊断结果、不执行 ERP 业务写操作。

## 构建与验证

需要 Node.js 24.12 或更高版本。本次开发实际使用 Node.js 24.21.0、npm 11.19.0。依赖使用完整版本号并保存在 `package-lock.json`。

```powershell
Set-Location E:\ai\holmesgpt\examples\erpnext-support\frontend
npm ci
npm test
npm run typecheck
npm run build
```

`dist/` 由工作台服务同源托管。企业版本的隔离实例使用 `http://127.0.0.1:8875/`；原首版实验实例 `8765` 不由前端脚本停止。账号从该实例的服务端初始化文件获得，不在前端源码中配置密码。开发调试可运行 `npm run dev`，开发代理指向 `8875`；开发页面来源需由服务端显式授权，最终部署使用同源生产构建。

业务源文件是 `.ts` 和 `<script setup lang="ts">`，开启 `strict`。`build` 先运行 `vue-tsc`，再打包；Vite 转换本身不提供完整类型检查。采用 [Vue 官方 TypeScript 指引](https://vuejs.org/guide/typescript/overview) 和 [Element Plus 分页接口](https://element-plus.org/en-US/component/pagination)，保留原框架版本，仅新增锁定的 TypeScript 5.9.3 / vue-tsc 3.3.12。类型声明帮助发现开发错误，接口运行时权限和参数边界仍由服务端执行。

## 操作页面

- **工单工作台**：创建发货问题工单，按环境、状态、负责人及文本筛选，调整负责人。
- **诊断详情**：创建异步诊断任务，每两秒查询任务进度，展开实际工具记录与证据，查看确认事实、候选原因、缺失信息、限制、人工步骤、成功率与耗时。部分完成、失败和中断都有独立提示。人工处理记录后运行复核；仅管理员或审核员可以确认关闭。
- **案例库**：新增、编辑、检索案例，维护适用版本、证据要求、条件、人工步骤、复核方法和 HTTPS 来源。编辑后撤销原审核，管理员或审核员可通过或退回。
- **环境配置**：管理员维护授权地址、服务端凭据别名、实际版本、应用、允许读取的服务、日志来源与模型数据授权；已获环境权限的人员可执行实际连接与能力检查。首版已审查版本为 ERPNext 15.85.1 / Frappe 15.87.0。
- **企业账号**：仅管理员可创建账号、修改角色和环境授权、停用账号及重置密码。修改角色与授权使用明确的字段，密码重置走独立接口；提交后或请求失败后清空密码，不读取旧密码。当前页面禁止更改自身角色或停用自身。
- **审计查询**：仅管理员可按账号、操作、资源、执行结果及请求编号检索实际审计记录，展开已脱敏详情，并查看工作台数据库、队列和执行进程的实际状态。

工单、案例、环境、账号和审计列表采用服务端分页与筛选，默认每页 20 条，可选择 50/100 条。切换筛选返回第一页，旧请求结果不会覆盖更新后的页面。环境和负责人选择器支持输入名称继续检索。所有接口错误复用同一展示方式，保留 HTTP 状态和服务端请求编号；管理员可以据此查询审计。导航权限仅改善页面使用，服务端仍逐次验证账号与环境授权。

运行采集器通过可空的服务端别名引用，数据库、Redis 和应用读取范围用复选框选择。别名不会提供 Token 编辑入口。能力页面将 ERP 版本及对象权限与独立采集器的容器状态、健康检查和 Redis PING 分开显示，仍然不能凭运行健康确认发货业务完成。

会话使用服务端 Cookie；修改请求携带 CSRF 校验。密码登录后立即清空，不写入浏览器持久化存储。证据、日志与案例内容按文本展示，不作为 HTML 执行。HTTP 403 显示为权限不足，接口失败不会用静态样例填充。

## 测试范围

`src/**/*.test.js` 使用显式 HTTP mock 验证前端行为：Cookie/CSRF、请求编号、403/401、错误与空态、证据文本转义、最新复核、角色控件、服务端分页与筛选、账号授权与密码清空、案例提交和环境能力反馈。测试与 E2E 脚本保留 JavaScript，业务源码和 Vue 页面使用 TypeScript。这些组件测试不证明 ERP 或模型可用。真实 ERP 故障结果与完整模型调用情况由实验室及服务端验证记录单独报告。

本次实际通过严格类型检查、生产构建、49 项显式模拟测试和 23 个真实企业页面闭环检查点（31.528 秒）。两轮失败及修复原因分别保留；企业闭环只使用不可用 `.invalid` 数据源，诊断 4 次调用成功 0/4、复核未完整通过后人工例外关闭，没有实际 ERP 或模型调用。分层结果、失败摘要与安全截图见 [ENTERPRISE_TEST_RESULTS.md](ENTERPRISE_TEST_RESULTS.md)。

企业版本的真实页面测试必须明确给出 **8875 实例自己的**初始化账号文件。脚本只修改服务器创建响应确认属于本轮的随机 QA 账号，成功流程结束后将其停用并移除环境授权；失败报告记录清理结果，创建结果不明确时不会仅凭账号名称停用。它不修改已有账号，不连接真实 ERP 或写 ERP。可选队列闭环只对显式指定的 `.invalid` 不可用测试源执行。

```powershell
npm run test:enterprise -- --url http://127.0.0.1:8875 --credentials <该实例initial-login.json绝对路径>
# 可选：仅给新 QA 账号短暂授权本机实验环境，验证保存和移除
npm run test:enterprise -- --credentials <该实例initial-login.json绝对路径> --environment-id <本机实验环境编号>
# 明确使用企业实例自己的 .invalid fixture，验证真实队列和人工例外关闭；不证明 ERP 效果
npm run test:enterprise -- --credentials <该实例initial-login.json绝对路径> --unavailable-fixture --environment-id <不可用fixture环境编号> --delivery-note QA-UNAVAILABLE
```

此脚本使用全新 Edge 上下文，验证创建、角色修改、密码重置、非管理员权限拒绝、账号停用及会话撤销、实际登录错误编号、真实审计检索/接口分页、系统状态和原四页。启用上述 fixture 选项时还创建新 QA 工单，观察真实队列的部分完成/失败证据，记录人工核对，重新复核并显式人工例外关闭；不会声称库存已经修复。每个检查点属于同一次浏览器流程，不应当作独立故障场景。脚本不导出密码、Cookie、HAR、trace 或登录状态；报告和已登录的非敏感截图写入 `.qa/` 唯一目录。最新企业验证状态见 [ENTERPRISE_TEST_RESULTS.md](ENTERPRISE_TEST_RESULTS.md)。

`npm run test:browser` 用全新临时浏览器环境验证本机已安装 Edge 的无界面启动，不连接用户日常浏览器配置。不需要下载或覆盖现有浏览器。

本地实验室和工作台启动、真实测试单据生成后，可执行真实界面集成测试：

```powershell
npm run test:e2e -- --delivery-note <实验室实际发货单号> --environment-id <工作台环境编号>
```

该流程读取本机初始化账号文件，创建标明 QA 的工单，调用真实诊断与复核，只记录人工处理说明并人工关闭工作台工单；不写 ERP。另创建无环境权限的 QA 分析员测试真实 403、空态和角色控件。随机 QA 密码只在进程内存中存在，账号不会获得 ERP 环境访问权限。结果与登录后的非敏感页面截图保存在 `.qa/` 的唯一目录。没有 HTTP mock、HAR、trace 或保存的登录状态。测试脚本只接受 `127.0.0.1` 工作台与 `127.0.0.1:8090` 实验室地址。

扩展流程还通过真实页面验证案例创建、检索、人工审核、编辑撤销审核，以及同一隔离站点的环境配置创建、独立采集器检查、编辑与删除。清理只针对本次流程自己创建的案例及重复环境配置，不删除已有工单、ERP 单据或其他配置。关闭的 QA 工单和没有环境权限的 QA 账号保留，便于核对审计记录。

独立部署容器可执行以下真实登录与四页空态检查。必须明确提供该容器自己的初始化账号文件，不读取或复用日常浏览器登录状态。

```powershell
node e2e/deployment-smoke.mjs --url http://127.0.0.1:8766 --credentials <该部署实例的initial-login.json绝对路径>
```
