# 单企业多账号版本升级说明

v2 面向一个企业内部的管理员、售后分析员与审核员。它在原 HolmesGPT / ERPNext 库存售后工作台上补充持久化任务、共享账号和审计管理，继续使用现有业务诊断与证据规则。企业部署是新的随机项目，入口为 `http://127.0.0.1:8875`；原 v1 的 SQLite、8765 页面、实验数据与报告作为历史保留，升级不会自动接管或覆盖。

## 当前实现

| 模块 | v2 行为 |
| --- | --- |
| 持久存储 | SQLAlchemy 2 复用主锁，PostgreSQL 保存工单、证据、账号、会话哈希、审计及任务租约；Alembic 通过独立迁移账号执行 DDL |
| 调度执行 | Celery / Valkey 与独立 worker，数据库保存排队、进度和租约，重复消息不能重复认领；超期任务保留步骤并标记中断 |
| 内部协作 | 管理员创建账号、分配角色及环境授权、停用和重置密码；账号权限或密码变化撤销会话，服务端逐次校验作用域 |
| 审计排查 | 操作、资源、结果和请求编号独立记录；管理员分页检索脱敏详情，应用数据库账号不能修改或删除既有审计事件 |
| 页面 | Vue 3 / Element Plus 保留原版本，业务源码与 Vue 页面改为严格 TypeScript；保留四页闭环，新增企业账号、审计查询与统一错误编号展示 |
| 部署监控 | nginx 仅通过本机 8875 提供入口；数据库、队列和可选 Prometheus 位于内部网络，API/worker 使用独立连接文件和健康/就绪检查 |

原 `Tool` / `Toolset`、`ToolExecutor` 和 `ToolCallingLLM.call_stream` 继续执行获准的 ERP 只读工具，报告继续保存事实、候选原因、证据编号、缺失信息、建议和调用记录。企业层改变持久化、协作和任务调度方式，没有替换诊断引擎；工作台写入自己的工单与审计，不执行 ERP 自动修复。版本限制、证据充分性和人工关闭要求继续适用。

## 新部署与依赖

按 [enterprise/README.md](enterprise/README.md) 创建新运行目录、镜像及项目。所有依赖保持固定版本：原 Python 主锁和 `LICENSE` 未修改，企业新增包位于 `enterprise/requirements.txt`，前端新增 TypeScript / vue-tsc 位于 `frontend/package-lock.json`。构建使用 Python 3.12；不会把本机初始化登录文件、旧数据库、ERP 密钥或旧报告复制进镜像。

数据库迁移账号与应用账号分开。应用账号没有数据库/Schema CREATE 权限，迁移凭据只挂到迁移服务；队列密码、数据库连接、指标 Token 从私有文件读取。网页只填写服务端已有凭据和采集器的别名，不提供 ERP、数据库或模型密钥编辑入口。外部 ERP origin 与模型数据授权必须由部署方明确配置，初始 allowlist 为空。

`/health` 仅表示进程存活；`/ready` 检查工作台数据库、队列及近期 worker 心跳。系统状态和容器健康不能证明库存故障已经解决，Prometheus 指标也不能代替业务证据。

## 旧 SQLite 的显式复制迁移

先保留旧镜像/代码、备份与运行目录，在受控维护窗口停止旧库写入。以另一全新空 PostgreSQL 目标及其私有迁移连接文件进行 dry-run，核对数量后才使用 `--apply`。完整命令与批次限制见 [持久层迁移说明](../../holmes/erpnext_support/persistence/README.md)。

源数据库以 SQLite `mode=ro` 打开，拒绝来源/目标相同、目标已有记录、链接路径或不合法格式。记录在一个事务内复制，中途失败不会留下部分业务数据；源文件保留。会话不复制，账号重新登录；旧排队/运行任务保留证据并标记中断，不自动重放。原密码哈希、账号授权、工单、人工记录、案例与审计保留，ERP 凭据文件需另外经授权受控复制。

新实例完成只读核对和真实复核后，才由部署方决定切换入口。恢复与回退使用保存的旧镜像或另一个空目标，不能把新 schema 直接交回旧程序，也不能在运行中的库覆盖、盲目 downgrade 或回滚 ERP 数据。工作台备份不含 ERP 数据库本体，但含敏感的业务证据、诊断结果、账号与会话状态，需要受控加密和留存。

## 试点边界与验证口径

当前实现支持单企业内部多账号，不宣称已完成多企业租户隔离、OIDC、MFA、HA、跨机队列故障测试或生产规模压测。当前网关入口仅绑定本机；企业正式接入还需部署方完成域名/TLS、访问管理、账号流程、备份演练、监控告警、ERP 权限审查与试点验收。已有 egress 网络不是全网段的网络层出口限制，工具与 HTTP 接入仍须按授权白名单使用。

接入企业 HTTPS 域名时，应在新实例服务端 `workbench_origins` 中配置精确的 HTTPS origin，并启用 `secure_cookies=true`；API 不信任任意客户端代理头，不能依靠伪造的 `X-Forwarded-Proto` 设置安全会话。当前回环 HTTP 演示使用默认关闭的 Secure 标记，不应直接复制到对外入口。凭据、备份与证据保留策略由受控部署文件维护，网页只管理授权范围和业务记录。

组件/API mock、真实 PostgreSQL/队列合同测试、浏览器检查点和真实 ERP 场景分别记录，重复回归不累加成新的故障场景。企业队列 `.invalid` fixture 故意使用不可用保留域名及无效凭据，只验证排队、执行、规则降级、部分完成和留痕；它不连接真实 ERP，不能当成故障根因命中率。

本次没有真实模型调用，不能声称模型效果、成本、延迟或投产能力已经验证。原首版真实 ERP 结果是历史证据，不能自动当作 v2 验收。v2 最终实际结果见 [ENTERPRISE_TEST_REPORT.md](ENTERPRISE_TEST_REPORT.md)，原 [TEST_REPORT.md](TEST_REPORT.md) 保留首版历史结果。前端本次分层执行记录见 [frontend/ENTERPRISE_TEST_RESULTS.md](frontend/ENTERPRISE_TEST_RESULTS.md)，部署实际记录由 [enterprise/VALIDATION.md](enterprise/VALIDATION.md) 维护。
